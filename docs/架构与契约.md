# PuerFlow 架构与契约

编排、沙箱与桌面基于 [Shannon](https://github.com/Kocoro-lab/Shannon)；策略执行走本仓 Python LangGraph Worker。面试口径：不是从零复现 Go/Rust，而是 LangGraph 接入与跨语言契约联调。

## 运行时拓扑

```
Client / Desktop :3000
    │  HTTP + SSE
    ▼
Go Gateway :8080
    │  gRPC
    ▼
Go Orchestrator :50052  ←→  Temporal :7233
    │
    ├─ gRPC RunStrategy ──► Python LangGraph Worker :50053
    │                         │
    │                         ├─ Redis Stream  shannon:workflow:events:{workflow_id}
    │                         └─ gRPC ──► Rust Agent Core :50051（WASI + workspace）
    │
    └─（LANGGRAPH_WORKER_ENABLED=0 时回退）原 ExecuteAgent / llm-service

PostgreSQL · Redis · Qdrant（compose profile `qdrant`，默认可关）
```

`LANGGRAPH_WORKER_ENABLED=1` 时 Simple / DAG / Research / Swarm 在 Temporal 工作流开头短路到 Worker；旧大图仍保留，可用环境变量关掉 Worker 回退。

## 控制面契约（`protos/strategy/strategy.proto`）

| RPC | 方向 | 作用 |
|---|---|---|
| `RunStrategy` | Go→Py | 按 `StrategyKind` 跑 Sample/DAG/Research/Swarm |
| `Cancel` | Go→Py | 置 `cancel_event`；图循环与 LLM 返回后检查 |
| `GetStatus` | Go→Py | 进度 / 结果 / 预算 |
| `ApproveDecision` | Go→Py | 人工审批；`require_approval=true` 时 Worker 会等 |
| `BudgetReport` | Go→Py | `hard_stop` / `degrade` |
| `InjectSessionContext` | Go→Py | Session history + Qdrant hits |
| `Health` / `Ready` | 探测 | Ready 在 Redis 可选时仍 ready=true，并列出 missing |
| `GetFailoverHint` | Py→Go | 策略失败建议降到 Sample |

事件面不另造总线：Worker 写 Redis Stream，Gateway SSE 按 Shannon 字段（`workflow_id/type/agent_id/message/payload/ts_nano/seq`）续传。

## 沙箱

Worker `SandboxClient`：

- `ExecuteTask` + `code_executor`：Python WASI
- `SandboxService`：workspace `FileRead` / `FileWrite` / `ExecuteCommand`

查询里有 ` ```python ` 围栏时才会调沙箱。`SANDBOX_OPTIONAL=true`（默认）时 Agent Core 不可达会跳过，不让策略失败。

## 记忆

Go Activity 在 `RunStrategy` 前调用 `FetchHierarchicalMemory`（Session 近期 + 语义，底层可走 Qdrant/pgvector）。Worker `load_memory` 再叠 `session.history`、`qdrant_hits`、`context.agent_memory`。

可选：`docker compose --profile qdrant up` 拉起 Qdrant `:6333`。默认 compose 不强制依赖它。

## 已知边界（诚实）

1. **llm-service 未删除。** Agent Core 工具、分解、回退路径仍可能用它。策略主路径已切 Worker，不是双 Agent 并行跑同一 query（Worker 开启时 DAG/Research/Swarm 不再走旧大图）。
2. **审批。** RPC 与 Worker 内等待已接通；Shannon 原 HITL 信号没有全部重写成同一套 UI 流程。Gateway 需调 `ApproveDecision` 或走 Temporal signal → `ApproveLangGraphDecision`。
3. **Qdrant。** 注入通道在；默认栈仍以 Shannon vectordb 配置为准，不是「每条任务必经独立 Qdrant 集群」。
4. **Desktop。** 仍是 Shannon Desktop，连 Gateway `:8080` SSE。未改 UI 协议。
5. **取消粒度。** 协作式：节点间隙与 LLM 返回后检查；无法在阻塞的第三方 HTTP 中间硬杀。
6. **模块路径。** Go module 仍是 `github.com/Kocoro-lab/Shannon/...`（版权在 LICENSE，未改模块名以免牵动全部 import）。

## 本地冒烟

无 LLM Key 时：

```bash
# deploy/compose/docker-compose.override.yml 可设 MOCK_LLM=true，Redis 映射 16379
docker compose -f deploy/compose/docker-compose.yml up -d --build langgraph-worker orchestrator gateway
curl -X POST http://localhost:8080/api/v1/tasks \
  -H "Content-Type: application/json" \
  -d '{"query": "What is the capital of France?", "session_id": "demo"}'
```

Temporal UI：http://localhost:8088  
Gateway：http://localhost:8080  
Desktop web：`cd desktop && npm install && npm run dev` → http://localhost:3000
